# Mahi UI Verse Quality Policy

## Primary principle

**Useful > numerous**

A resource should provide practical value to:

- frontend developers
- UI developers
- UX designers
- web developers
- design engineers
- creative developers
- accessibility engineers
- product designers

## Required

- Name
- Official website
- Category
- Useful description

## Recommended

- Demo
- Documentation
- GitHub
- Video
- Framework
- Technology
- Pricing
- License
- Tags
- Last verified

## Never Guess

Unknown information must remain:

unknown

or:


eeds-review

## Duplicate policy

A resource is a true duplicate when:

1. Canonical URL is identical
2. Same GitHub repository
3. Same exact resource is repeated
4. Only tracking parameters differ

Different meaningful paths are allowed.

Example:

https://example.com/components

https://example.com/templates

are not automatically duplicates.

## Tracking parameters

These may be removed during canonicalization:

- utm_source
- utm_medium
- utm_campaign
- utm_term
- utm_content
- fbclid
- gclid

Meaningful query parameters must remain.
